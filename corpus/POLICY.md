# Ichiwatashi 语料池的准入规则

> **这份文件的作用是「先定规则、再抓样本」。** 反过来做会抓回一堆混合来源，
> 然后每一条指标的分歧都变成「这是画风差异还是来源差异」——**而那个问题无法从数据回答**。

---

## 一、池子的一句话定义

**日式萌系向 ACG 的像素画。** 不是「像素画」——后者会把西方像素游戏、8-bit 复古风、
工业图标、地图瓦片、程序化生成的纹理全部吸进来，而**它们的描边约定、配色结构、形体语言
与目标是不同的**，混在一起之后参照表就没有意义了。

## 二、为什么这条是硬要求（不是偏好）

**已经实测到的代价。** 语料池的前身是 **TH123 的 120 张精灵**，而那一组参照值被拿去
判 **TH155** 的精灵，结论是：

| | TH123 参照 | TH155 实测 |
|---|---|---|
| `outline_variation` 中位数 | **0.726** | **0.003** |

**而两代都是正确作品。** 于是 TH155 那一代**每一张**都被报警（`outline_variation` 远在 p05 之下）。
**这不是判据算错，是参照被来源锁死了** —— 而当时没人知道 120 张只来自一款游戏。

**所以来源必须是一等字段，不是备注。**

## 三、准入三门

### 门 1：排除（一票否决）

任一命中即 **拒收**，并记录拒收理由：

| 排除项 | 为什么 |
|---|---|
| **非 ACG**：西方像素游戏、8-bit 复古、工业/地图/图标素材 | 描边与配色约定不同 |
| **非萌系向**：写实比例、硬核军事/恐怖题材的像素 | 形体语言不同 |
| **程序化生成**：噪声纹理、瓦片自动生成、AI 生成 | **不是人手画的**，而判据要测的正是手绘约定 |
| **已被重编码的**：JPEG 重建、缩放过的、调色板被量化过的 | **量化会把 `colours_used` 钉死**（已实测：第二语料的 16 就是我的量化值，那一行不是艺术证据） |
| **来源不明**：找不到出处的「网络像素图合集」 | 无法记录来源世代 |

### 门 2：采纳（至少两项正面证据）

| 证据 | 例子 |
|---|---|
| **出处是 ACG 作品** | 某游戏/动画/同人本的拆包或扫描 |
| **作者是 ACG 画师** | 有署名的 pixiv/Twitter 作品 |
| **元数据是 ACG 的** | 原始文件名/目录结构属于某作品（`data/character/<char>/`、`<作品>_<角色>`） |
| **风格可判** | 萌系比例、大眼、简化五官、日式配色 |
| **无损** | 8bpp 索引色 / 无损 PNG，**未经重编码** |

**只有一项正面证据 → 进「待议」，不进参照表。**

### 门 3：隔离（合成与处理过的另立一栏）

**任何我造的、改过的、放大过的样本，一律 `derived: true` + `derived_from` 指向源 sha256。**

理由是一条已经踩过的教训：**`pixel_scale` 的反例是我合成的放大图**。
它必须能被拿来验证判据，**但绝不能进参照表** ——
否则「真手绘的分布」里就混进了我自己的合成物，而那是循环论证。

## 三之二、而这三门在真实世界里挡住了什么（2026-10-12 的调查）

**一份对 18 个来源的作品调查**（`E:\DaShaoHuo\cache\tmp\ichiwatashi-research-round2-artwork.md`，
逐条读条款、引原文）给出了三门在现实中的对照。**结论比预想的窄，所以它值得写在这里。**

### 一、最大的「对味」池，恰好是条款上不能碰的那个

| 来源 | 规模 | 为什么不能收 |
|---|---|---|
| **pixiv うごイラ** | **307,222 件** | 第 14 条：未经作者同意不得**転載**；且**禁止情报解析（含 AI 学習）**而其结果有害作者利益 |
| **pixiv `ドット絵` 标签** | **284,454 件** | 同上。**这是全世界最对味、最大的萌系像素画池，而它禁止存储与未经同意的解析。** |

**而 CC0 那一批是西式的**（Duelyst · OpenGameArt · itch.io · Kenney · LPC）——
**所以「对味」与「可存」这两件事，在最关键的一处正好相反。**

### 二、**「对成人向宽容」不等于「可以复用」** —— 这一条要看清楚

调查里有四个来源**明确允许成人向**，却因为再配布条款照样进不了语料：
`素材置き場` · `素材屋ここ` · `damagedgold` · `ドット絵世界`。

> **别把「对成人宽容」读成「可以复用」。** 而这条对**本工程格外要紧** ——
> **因为它是一个成人向工程，所以很容易把「这个站允许成人内容」当成「这个站允许我用」。**
> **两件事之间没有关系。**

### 三、而最常见的四个陷阱条款，形状很清楚

| 陷阱 | 原文形状 | 它挡住的 |
|---|---|---|
| **二次配布禁止** | 「二次配布は禁止です」「再配布を許可しません」 | **杀死大多数日本免费素材的那一条** |
| **AI 学習 / 生成 AI 加工禁止** | 「乘AI学習」「生成AIでの加工を禁止」 | 与本研究无关（我不训练模型），**但条款不看我的意图** |
| **ジェネレーター素材禁止** | 「アイコンやフォント作成などのジェネレーターの素材として使用する事も禁止」 | **正对着这类项目** —— 我既是测量器又是生成器 |
| **自动采集禁止** | 「プログラム等を用いて自動的・体系的に収集・抽出」を禁止 | **等于点名自动化语料构建** —— 而那正是 `tools/corpus.py` 在做的事 |

> **第四条最值得单独看**：它不是「不许用素材」，而是**不许用程序去采集素材**。
> **而本工具的全部语料都是由脚本采的** —— 所以这一类来源不只是「不能用」，是**「不能用我正在用的方式去接触」**。
> **这一条我以前没想到，它比前三条更贴。**

### 四、所以能存的语料，与能看的参照，是两回事

**这个区别不是我的偏好，是条款逼出来的。** 已写进 `SOURCES.md`：

| | 谁 |
|---|---|
| **可入语料**（能下载、能存、能进参照表） | **Duelyst / OpenDuelyst**（CC0 · 600+ 动漫风像素单位 · 攻击/待机/跑/死亡四套动画）· **ぴぽや**（日本站里唯一明确允许再配布的个人站）· OpenGameArt CC0 + 它的 HuggingFace 镜像 · LPC（CC-BY-SA，带署名义务）· itch.io 的 CC0 项 · Kenney |
| **只能参照观看**（可读、可分析画面，**不落地、不进参照表**） | pixiv 的全部 · The Spriters Resource（商业提取物）· 以及任何条款不明或读不到的来源 |

**而「萌系约定」这一块因此有一个诚实的空缺**：
**它大概只能从「参照观看 + 逐作者授权」来，而存放的语料会偏西式。**
**这是结论，不是没查完。**

### 五、而镜像 / 阅览站改变什么、不改变什么（2026-10-12 实测）

**本机装了 `Pixiv-Viewer 1.37.6`**（`D:\Pixiv-Viewer`，发布者 `Yumine Sakura`；
上游 `asadahimeka/pixiv-viewer`，预览站 `pixiv.pictures`）。它**能下载与导出** ——
`动图下载 ZIP / GIF / WebM / APNG / MP4 / AVIF` · `支持动图 ZIP 原文件下载` · `Tampermonkey 支持`。

**而它的 README 自己写着三句话，那三句决定了它的用途边界**（原文）：

> 本项目与 pixiv.net（ピクシブ株式会社）**无任何隶属关系**。
> **本项目网站、APP 所展示的所有作品的版权均为 Pixiv 或其原作者所有。**
> 本项目**仅供交流与学习，不得用于任何商业用途。**

| 它改变了什么 | 它不改变什么 |
|---|---|
| **技术上**：不必登录都能看到作品的**元数据与缩略**；登录后可**读原图**；动图能整包取出 | **权利**：它明确声明**版权不归它**。所以「从镜像取」与「从 pixiv 取」**在权利上是同一件事** |
| **工程上**：`うごイラ` 的 **ZIP 就是「帧 + 延迟表」** —— 与本仓库 `frames.py` 处理 `.pat`、`Timeline` 处理帧序列**是同一类东西** | **条款上**：pixiv 第 14 条禁未经同意的転載与有害的解析；而**镜像站再分发不了它没有的权利** |

> **所以本工具可以把镜像用于「参照观看」，不可以把它当作采集通道。** 而这条不是我保守 ——
> **是那个工具自己在免责声明里把版权划给了别人。** 一个工具的技术能力**不能**被读成使用许可。

**而有一条真的用途**：`うごイラ` 的 **ZIP 原文件**能让「帧序列 + 每帧延迟」被**原样检查**，
于是 `Timeline` 的时长那一栏（现在写着「TH105 的 `.pat` 里没有时长，那大概在游戏代码里」）
**至少能从这种格式上确定一件事：延迟表是可以独立于像素存在的、且这是通行做法。**
**那是一条可以引用、而不需要转发任何画的结论。**

## 四、来源世代（`generation`）是一等字段

**已实测：`TH105 ≡ TH123`**（四个角色、六个指标、12 个对照到小数点后三位一致），
**所以世代只需两档，不是三档**：

| `generation` | 含义 |
|---|---|
| `th105/th123` | 2008–2010 商业格斗精灵 |
| `th155` | 2017 商业格斗精灵 |
| `ugoira` | 2010s うごイラ（**渲染帧，不是精灵** —— 判据会识别并明说） |
| `other_acg` | 其他 ACG 来源 |
| `synthetic` | **我造的，永进参照表** |

**参照表的每一行必须标注它来自哪个世代。** 没有这一栏，TH123 那种误报会再发生一次。

## 五、记录什么，不记录什么

**照「语料事实可提交、样本本体不进仓库」的形态**（同族工具已有先例）：

```
corpus/
  POLICY.md          ← 这份
  README.md          ← schema 说明
  manifest.jsonl     ← 一行一条事实，可提交、可 diff
  sources.jsonl      ← 每个来源一条：URL、许可态度、抓取方式、时间
```

**样本本体存在仓库外**（当前：`E:\DaShaoHuo\downloads\ichiwatashi-corpus\`），
`manifest.jsonl` 里只留 `sha256` 与 `path_hint`。**sha256 是身份，路径只是提示。**

**为什么不存样本**：一半原因是体积与许可，**另一半更重要** ——
**测量才是贵的那部分，而样本是可复现的**。（同族的 Torikago 丢过一次 248 条测量记录，
清单与记录都写在仓库里正是为了这个。）

## 六、指标可用性随来源而变（已实测，必须一起记）

**同一批样本，不同指标的可信度不同**：

| 指标 | 可用性 | 依据 |
|---|---|---|
| `bbox_fill` · `pixel_scale` | **任何来源都可用** | 纯几何量，对调色板 0% 变化 |
| `outline_variation` + `predictability` | **必须按世代分档读** | TH123 0.726 vs TH155 0.003 |
| `colours_used` | **只在无损来源上可用，且必须记录用了哪个调色板** | 92.5% 的精灵会随调色板变，median spread 27 |
| `clusters` · `dither_pixels` · `isolated_rate` | 可用，但需固定调色板 | 常动，幅度小（相对值 0.01–0.03） |

**这一栏随 `generation` 一起写进 `sources.jsonl`。**
